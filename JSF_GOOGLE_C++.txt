[JSF AV C++ Coding Standards 요약]

1. 개요 및 배경
- 정의: F-35 전투기(Joint Fighter)의 비행 제어 및 항공전자 소프트웨어 개발을 위해 록히드 마틴 주도로 제정된 고신뢰성 코딩 표준 (2005년 공개).
- 철학: 안전이 최우선인 시스템(Safety-Critical System)에서 오류를 유발할 수 있는 C++ 기능의 90%를 제한하고, 실행 결과를 완전히 예측할 수 있는 안전한 서브셋만 사용.

2. 3대 핵심 제약 사항 (결함 원천 차단)
- 동적 메모리 할당 금지 (new, delete, malloc 금지): 비행 중 메모리 부족(Memory Leak) 및 메모리 파편화로 인한 시스템 지연을 방지하기 위해 전역/정적 변수 및 고정 크기 메모리 풀만 사용.
- 예외 처리 금지 (throw, catch 금지): 에러 발생 시 프로그램의 실행 타임라인과 복구 시점을 정확히 예측(Deterministic)하기 어렵기 때문에 반환 값(Return Code) 기반의 예외 처리를 수행.
- 재귀 함수 금지 (Recursion 금지): 스택 오버플로우(Stack Overflow)로 인한 시스템 다운을 막기 위해 모든 반복 작업은 루프(for, while)로만 구현.

3. 주요 설계 및 품질 규칙
- 분기 복잡도 제한 (AV Rule 3): 함수의 순환 복잡도(Cyclomatic Complexity)를 20 이하로 제한하여 인간이 검증 가능한 단위로 코드 분할.
- 상속 및 다형성 제한: 실행 시점 오버헤드와 예측 불가능성을 줄이기 위해 상속 깊이를 제한하고 가상 함수 사용을 최소화.
- 표준 라이브러리 사용 제한: 입력/출력 시간이 가변적인 기능 및 크기가 늘어나는 STL 컨테이너(std::vector 등)의 사용을 엄격히 통제.

4. 현대적 의의 및 한계
- 의의: 생명과 직결된 극한의 임베디드 환경에서 C++을 안전하게 사용하는 발판을 마련하였으며, 이후 MISRA C++, AUTOSAR, NASA F-Prime 등의 모태가 됨.
- 한계: 2005년 표준(C++98 기준)이므로 최신 C++(C++11 이후)의 스마트 포인터나 constexpr 같은 안전 장치가 반영되어 있지 않음. 현대 프로젝트에는 C++ Core Guidelines와 병행 참조 권장.


구글 C++ 스타일 가이드 핵심 요약

1. 예외 처리 금지
- try-catch 및 throw 사용을 원칙적으로 금지합니다.
- 반환 값이나 상태 객체(absl::Status)를 사용하여 에러를 처리합니다.

2. 명명 규칙 (Naming)
- 클래스 및 함수: CamelCase (예: MyClass, MyFunction)
- 일반 변수: snake_case (예: local_variable)
- 클래스 멤버 변수: 끝에 언더바 추가 (예: member_variable_)
- 상수: k로 시작하는 CamelCase (예: kMaxCount)

3. 포맷 및 가독성
- 들여쓰기: 탭(Tab) 사용 금지, 오직 공백 2칸(2 Spaces)만 허용합니다.
- 줄 제한: 한 줄의 길이는 최대 80자를 넘지 않아야 합니다.

4. 상속 및 기능 제한
- 다중 상속은 순수 가상 인터페이스를 상속하는 경우를 제외하고 엄격히 제한합니다.
- 완전히 검증된 C++ 표준 기능만 보수적으로 도입합니다.
